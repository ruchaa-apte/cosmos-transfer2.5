# TartanDrive2 Weather Augmentation

Generate synthetic rainy/snowy versions of TartanDrive2 off-road driving footage using
Cosmos Transfer 2.5, for training/evaluating off-road robot perception under adverse weather.

## Prerequisites

- TartanDrive2 source images available locally, e.g. `.../data/tartandrive/<sequence>/image_left_color/*.png`
  (path is hardcoded as `TARTANDRIVE_ROOT` at the top of each script — update it to match your machine)
- Project venv set up: `.venv/bin/python` (repo root) for Cosmos Transfer inference;
  `python3.10` with `opencv-python`, `torch`, `transformers` for the control-extraction scripts
- Multiple GPUs recommended (scripts default to splitting work across GPUs 0-2 or similar;
  adjust `--n-gpus` / `CUDA_VISIBLE_DEVICES` for your machine)
- `ffmpeg` on PATH

This directory ships only the pipeline **scripts, prompts, and generated spec JSONs**.
`data/`, `outputs/`, and `logs/` are gitignored — they're large (dataset frames, generated
videos, run logs) and regenerated by running the pipeline below.

## Pipeline

Run from the repo root unless noted otherwise.

1. **`01_images_to_mp4.sh [FPS]`** — converts each sequence's PNG frames into `data/<seq>/input.mp4`
   (default 10fps). Update the hardcoded `SEQUENCES` list and `TARTANDRIVE_ROOT` first.

2. **`02_extract_edge_control.py [--low 100] [--high 200] [--fps 10]`** — Canny edge maps,
   read directly from source PNGs (avoids re-encode artifacts) → `data/<seq>/edge.mp4`.

3. **`02b_extract_depth_control.py [--model small|base|large] [--fps 10] [--batch-size 8]`** —
   monocular depth via Depth Anything V2 → `data/<seq>/depth.mp4`. GPU required.
   Near=bright, far/sky=dark convention; uses 2nd-98th percentile normalization so sky doesn't
   dominate the range.

4. **`03_generate_specs.py [--guidance 5] [--control-weight 1.0]`** — generates one Cosmos
   Transfer inference spec JSON per sequence × weather condition → `specs/<seq>_<weather>.json`,
   plus `specs/batch_all.txt` listing all spec paths.

   *or* **`04_split_and_regen_specs.py [--max-seconds 15] [--guidance 5] [--control-weight 1.0]`** —
   splits `input.mp4`/`edge.mp4`/`depth.mp4` into ≤15s chunks and generates one spec per
   chunk × control modality × weather → `specs/chunks/`, with `batch_edge.txt`, `batch_depth.txt`,
   `batch_all.txt` for batched inference.

   *or* **`06_extract_kf_clips_and_specs.py [--n-gpus 3]`** — extracts 20s clips aligned to
   Alpamayo validation keyframes (1.6s history + prediction window) and generates multicontrol
   rainy specs per keyframe → `specs/kf_multi/`, with `batch_gpu{0,1,2}.txt` for splitting
   across GPUs.

5. **Run inference** with the repo's `examples/inference.py`, one process per GPU:

   ```bash
   CUDA_VISIBLE_DEVICES=0 .venv/bin/python examples/inference.py \
       --input-files tartandrive/specs/chunks/<spec1>.json tartandrive/specs/chunks/<spec2>.json ... \
       --output-dir tartandrive/outputs/chunks/ \
       2>&1 | tee tartandrive/logs/gpu0.log
   ```

   Run each modality (edge / depth / multicontrol) as a **separate** invocation — tyro only
   picks up the last `-i`/`--input-files` value if modalities are mixed in one command.
   Multicontrol needs a full GPU; don't run it alongside other inference jobs (OOM risk around
   50GB used). `make_remaining_batches.py` can regenerate batch files excluding specs that have
   already completed, for resuming partial runs.

6. **`05_build_html_deck.py [--out tartandrive/outputs/deck]`** — builds a self-contained,
   portable HTML deck comparing input | edge-rainy | depth-rainy | multi-rainy | edge-snowy |
   depth-snowy | multi-snowy per clip, for visual review.

7. **`07_cosmos_reason_critic.py`** — scores generated videos for weather realism and geometry
   preservation using Cosmos-Reason1-7B.

   ```bash
   # Live, in parallel with generation (pick a free GPU)
   CUDA_VISIBLE_DEVICES=4 python3.10 07_cosmos_reason_critic.py --watch \
       --video-dir tartandrive/outputs/kf_multi \
       --out tartandrive/outputs/kf_multi/quality_log.jsonl

   # Batch, after generation is done
   python3.10 07_cosmos_reason_critic.py --batch \
       --video-dir tartandrive/outputs/kf_multi \
       --out tartandrive/outputs/kf_multi/quality_log.jsonl
   ```

## Prompts

`prompts/rainy.txt` and `prompts/snowy.txt` (add snowy.txt if missing) describe the target
weather condition. **Prompt wording controls appearance; the control video controls structure**
— mismatched terrain keywords can override the control signal (e.g. `"flat grassy terrain"`
made the model generate green grass regardless of input; fixed by using `"dirt trail"` instead).
Always sanity-check that the prompt's terrain description matches the actual sequence before
running a full batch.

## Known findings

- Edge control generally outperforms depth control for this dataset — depth maps are too smooth
  for off-road terrain with large sky regions.
- Depth extraction convention: near=bright, far/sky=dark, matching the `car_depth.mp4` reference
  (mean≈67); avoid inverting, and normalize using the 2nd-98th percentile to keep sky from
  dominating the range.
- Source images are 1024×544; Cosmos Transfer snaps this to the 16:9 bucket and processes
  internally at 1280×704, reshaping outputs back to 1024×544.
